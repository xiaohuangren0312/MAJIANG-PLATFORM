# v3 补充设计：选手、队伍录入与 M.LEAGUE 风格榜单

更新时间：2026-09-05。本补充与 design.md 共同构成当前设计；涉及名单录入与榜单时优先本文件。

## 1. 录入入口和流程

管理导航增加「选手管理」「队伍管理」，入口始终显示当前赛事。

团体赛：创建赛事 -> 创建队伍 -> 添加选手并报名、分配队伍 -> 创建半庄并选择东南西北四名选手 -> 录入终局成绩/罚分/役满 -> 审核发布。
个人赛：创建赛事 -> 添加选手并报名 -> 创建半庄选人 -> 录入与发布，无队伍必填项。

新建赛事的队伍和选手列表为空，不再自动生成四名示例参赛人；原型初始两项示例赛事仍有虚构数据。数据为空时显示录入引导，未满足四名可出场选手时禁止创建半庄。

## 2. 选手与报名

原型字段：公开姓名/昵称、赛事唯一报名编号、所属队伍（团体赛）、参赛/停用状态。
正式版增加头像、本地选手档案关联、资料简介、报名时间、审核状态、联系方式（仅管理员可见，不进入公众榜单）、有效成员归属起止时间。

- 姓名可以重复，编号和内部 ID 区分身份；下拉选人展示姓名、编号和队伍，禁止用姓名作关联键。
- 正式版支持从全局选手库检索并“报名到当前赛事”，新建选手档案时不能自动报名其他赛事。原型直接创建赛事级报名记录，全局档案复用仍为后续实现。
- 管理页面支持新增、编辑、搜索、停用/恢复。不能删除已有战果的选手来消除成绩；停用保留历史。
- 团体赛可先录入未分配队伍的选手，但此状态不可出场。每项赛事独立管理其成员归属；其他赛事不受影响。
- 原型中的转队影响后续阵容选择，不回写既有半庄的 team_id 快照。正式版补充转队生效时间、原因和待赛阵容影响预览。

## 3. 队伍与成员

原型字段：队伍名称、简称、代表色、参赛/停用状态。正式版增加队徽、简介、队长、成员人数限制、每场同队出场限制等赛事配置。

- 队伍属于单一赛事，本赛事队伍名唯一；相同队名可出现在不同赛事，ID 必须不同。
- 队伍卡片显示成员列表与状态。「管理成员」跳转选手管理，新增时预选该队。
- 队伍停用保留已发布积分；其成员不可进入新建阵容。成员转队后仍能在原队贡献明细中看到历史贡献，标为“历史成员”。
- 个人赛的队伍管理入口显示不适用和前往选手管理的说明。

## 4. 对局阵容

四个座次从当前赛事的可出场名单选择，不再固定使用示例选手。
选人须同赛事、四人不同、报名有效、团体赛归属有效；正式版进一步按赛事规则校验同队人数、晋级资格、出场次数和排期冲突。

草稿中仅交换相同四人座次，终局点数随选手本人保留；有新人替换时原型将四人点数重置为起始点，并提示重新录入，防止把旧分数转移给新人。若被换下者存在罚分/役满事件，先处理事件再换人，不能悄悄删除。
已发布或锁定阶段的阵容只读；正式更正按成绩修订流程处理。旧队伍快照只在明确重新应用草稿阵容时更新，不随选手资料编辑自动变化。

## 5. 参考 ML 的榜单布局

参考 [M.LEAGUE 首页排行榜](https://m-league.jp/) 的队伍积分、分差、场数与个人榜类别，以及 [M.LEAGUE 统计页](https://m-league.jp/stats/) 的阶段切换和选手比较。使用欢雀楼自己的名称、色彩和成员资料，不复制官方队徽和选手照片。

### 队伍榜

阶段页签 + 当前分数口径 + 榜首摘要 + 队伍排行表。列：名次、代表色/队徽、队名、积分、距前一名、距榜首、已赛/已排场数、最近一场增减、原始累计走势、成员详情。
分差明确是与谁比较，不能只写“差”。计划总数仅根据实际已排赛程，不硬编码 ML 的赛季场数；未排全部赛程时标签是“已排”，不是预计完整赛季总场数。
点击队伍展开成员贡献：成员姓名、场数、基础贡献、队伍侧处罚、净贡献、当前/历史成员。阶段带入在队伍层单列，不分摊进选手战果。

### 个人榜

总积分 / 最高终局点数 / 平均顺位 / 头名率 / 连对率 / 避四率 / 场均积分等指标切换。提供阶段、当前所属队伍、选手关键词、最少场数和分数口径筛选；前三摘要与完整排名表并存。
表格显示名次、选手与编号、总积分、场数、平均顺位、1~4位次数、头名率、连对率、避四率、最高点数、罚分、役满次数。点击选手打开指标明细及累计走势。
队伍过滤在原型中按“当前所属队伍”筛选人员，但不改变这些选手的历史对局范围，页面明确该名称；正式版另外提供“当场代表队伍”的比赛范围筛选，不能混淆。

## 6. 数据口径

终局点数、顺位、比赛状态和出场记录足以计算：场数、基础/净积分、平均顺位、各位次数、头名率、连对率、避四率、最高终局点数、单场增减与时间序列。罚分和役满统计来源于独立事件。

- 均顺 = 实际出场顺位之和 / 场数；同分并列取所占名次中点。
- 本程序默认采用同位按所占顺位均分次数的统计政策，例四人同分各得 1~4 位次数 0.25，均顺 2.5；两人并列一位各得一位/二位次数 0.5。该政策作为欢雀楼明确的统计配置，不冒称已核实为 ML 官网全部历史榜单的同分口径。
- 头名率 = 一位次数 / 场数；连对率 = (一位 + 二位次数) / 场数；避四率 = 1 - 四位次数 / 场数。
- 场均积分默认使用未压缩原始净分 / 场数，不把阶段带入重复均摊。最高点数使用终局点棒数，允许负数，不等于最高净积分。
- 无出场记录的比率、均顺和最高点数显示“—”，不制造 0% 或 0 点。个人榜默认至少 1 场，可修改资格场数；同一统计指标相等并列。
- 关键词及当前队伍筛选只隐藏行，保留在当前资格范围内的排名；修改最少场数或指标会重排，注明为该条件下的统计榜。
- 队伍走势和个人走势表示按时间的原始累计，不包含压缩带入，与“竞技积分”不混用。
- 和牌率、放铳率、立直率、副露率、平均和牌点数、总局数等依赖逐局事件。当前显示“未采集”，后续增加逐局录入后才展示。

## 7. v3 状态及验收

已可演示：队伍新增/编辑、成员列表；选手新增/编辑/搜索、报名编号校验、队伍分配与停用；草稿阵容调整；两类榜单的上述指标与详情。所有数据仍仅存在页面内存，刷新后重置。

正式版尚需：全局选手库与赛事报名分离、头像/队徽上传、批量导入预览与去重、资料修改审计和成员有效期、报名/上场权限后端校验、对局排期和出场规则检查、公开只读入口及真实持久化。不得将演示原型用于正式成绩存储。

验收包含：空赛事不能开桌；个人赛无需队伍；同名不同编号；跨赛事队伍拒绝；未分配/停用不可出场；换队不改历史贡献；阵容重复拒绝；新人替换不继承旧战果；零场和同点统计；成员贡献合计与队伍原始净分相等；移动端入口可达与表格横向浏览。
