## 二、赛事组织与隔离

业务层级：平台 -> 赛事 tournament -> 阶段 stage -> 比赛日/轮次 -> 桌次 -> 半庄 match -> 四名对局选手及事件。不要把不同独立比赛误建成同一赛事的阶段。

创建赛事：名称、简称、个人/团体类型、参考组织及具体规则模板版本、起止日期、时区（默认 Asia/Shanghai）、场地、公开状态、管理员、初始阶段、报名/出场设置。模板默认 ML 计分；个人赛可改选协会、联盟、最高位战或自定义。组织参考只是模板来源，不决定是否可以使用某个计分方案。

- 独立比赛有独立报名、队伍、成员资格、阶段、规则版本、赛程、成绩、罚分、役满、结算和管理员授权。
- 全局选手身份可以复用，但每次报名生成赛事级参赛记录；队伍与成员归属按赛事和有效时间保存。对局保存成员快照，转队不回写历史。
- 管理后台顶部始终显示当前赛事。切换赛事时清除不适用的阶段、队伍、选手过滤条件；未保存的修改先提示保存或放弃，不能静默丢失。
- 管理员只管理被授权的赛事；平台管理员可跨赛浏览被授权范围。所有 API、数据库关联、异步任务、导出及附件路径都必须携带和验证 tournament_id。不是只靠前端下拉框过滤。
- “全部赛事”只用于总览/赛程/赛果查询，跨赛事榜单不提供一个合并总排名。不同规则和阶段的分数不能直接合成总榜。
- 个人赛隐藏队伍录入要求，队伍榜展示“不适用”，不会出现上一场团体赛的队伍数据。
- 开赛前可调整赛事类型；已有发布战果后不能直接切换个人/团体类型，需明确迁移方案。
- 归档保留记录，公开可见性独立控制；新增赛事默认为草稿。

## 三、规则模板与管理

计分引擎与赛事类型解耦。规则模板 -> 赛事规则版本 -> 半庄快照，任何改动均不静默覆盖历史。

| 模板 | 已核实的计分摘要 | 实施说明 |
| --- | --- | --- |
| M.LEAGUE | 25000 起始，30000 返还；最终顺位加分 +50/+10/-10/-30 | +50 已含头名奖励，不能再加 +20；同分分配与终局供托按该版本规则 |
| 日本职业麻将协会 | 25000/30000；+50/+10/-10/-30；官网列终局剩余立直供托不分配、错和罚 40P | 数值相似不代表与 ML 同一模板，供托和处罚政策必须分别保存 |
| 最高位战普通规则 | 30000/30000，无头名奖励，顺位马 +30/+10/-10/-30 | 不得误用 Classic 的 +12/+4/-4/-12；完整同分/供托/罚则须按具体规程版本核实 |
| 日本职业麻将联盟 | 独立参考组织，可选具体版本后配置 | 尚未完成现行完整参数核实，不预填伪装成联盟官方的固定顺位分；引擎需要支持按浮沉人数条件匹配的顺位表 |
| 自定义 | 由赛事管理页定义 | 显示“自定义”及版本，不冒充官方规则 |

规则表单：起始点、返点、计分单位、头名奖励与顺位马/最终顺位加分的明确表示、固定或条件顺位表、同分分配、余数处理、终局供托、处罚模板、役满类型与复合政策、榜单资格与同分决胜条件。

个人赛创建时默认仍可使用 ML 计分（继承用户原始默认要求）；主动选择其他参考组织时显示具体模板配置，不自动偷换为 ML。未核实或不完整的模板可保存赛事草稿，但不能用于正式发布成绩。

一桌结果计算：先按规则处理点棒与供托 -> 确定竞技顺位和基础积分 -> 独立记罚分 -> 得到个人净得分/队伍贡献。处罚默认不倒推改变该桌点棒顺位。

点棒校验必须随供托政策变化：ML 采用已分配完供托的最终点数；允许终局供托留存的模板校验“四人点数 + 剩余供托 = 起始总点数”，不能把 v1 的总点数必须等于 100000 硬套给全部比赛。

## 四、罚分设计（R01）

一场可有多条罚分，支持选手或队伍级处罚，录入：对象、扣分数额、处罚类型、原因、所属赛事/阶段/半庄（半庄可空）、发生时间、裁定者、公开说明、附件、规则版本和状态。

- 用户输入正数表示扣除，例如输入 20，账本记 -20.0 pt；不以负负得正的方式录入，不允许 NaN/无限值。系统允许 0.1 pt 精度；原因非空。
- 明确影响范围：仅个人、仅队伍、个人并计入所属队伍。个人赛禁止队伍范围。模板提供建议，不隐式把个人罚分重复扣到队伍。
- 队伍净分 = 成员本场基础贡献 + 应计入队伍的个人罚分 + 队伍专属罚分；每个处罚事件只记一次。仅队伍罚分不改个人榜，仅个人罚分不改队伍榜。
- 阶段是否压缩处罚单独配置：默认按净竞技分压缩，也可“基础分压缩，罚分全额带入”。预览明确两部分，已经在历史带入中吸收的罚分不得再次扣除。
- 表格并列展示点棒、基础积分、罚分、个人净得分、队伍贡献；处罚不要求一桌净分仍为零。
- 更正/撤销处罚留历史版本与原因，重建影响榜单；阶段锁定后更正遵守结算修订流程。

## 五、役满标记（R02）

役满作为独立成就事件，不是额外积分奖励，避免与已录终局点数重复计分。

字段：赛事、阶段、半庄、选手、局（东/南几局）、本场、役满类型列表、复合倍数、和牌方式（自摸/荣和）、放铳者（适用时）、备注、可选照片、审核状态。类型字典依规则版本控制，不能无条件允许数え役满或地方役。

同一半庄允许多名选手、多次役满；同一次复合役满是一条事件带多个役种。统计分别显示“发生次数”“累计倍数”，避免将双倍役满算作两次和牌。支持赛果徽章、详情展示、个人/队伍役满次数、仅看役满筛选。若比赛有额外奖励积分，必须另建明确的奖励规则/积分事件，不由标记自动产生。

## 六、多阶段结算与可编辑预览（R05）

阶段可为预赛/常规赛/半决赛/决赛或自定义名称、顺序、晋级名额、赛程和规则版本；不固定 ML 队伍数或阶段数量。

状态：筹备 -> 进行中 -> 待结算 -> 已结算/锁定。结算需要当前阶段全部有效半庄发布或明确取消，待审核处罚/役满处理完毕，不能用页面筛选后的部分比赛结算整个阶段。

### 结算分数口径

- 本阶段原始贡献：仅本阶段半庄基础积分及本阶段处罚。
- 本阶段竞技分：上阶段有效带入 + 本阶段原始贡献。
- 全赛事原始累计：各场未压缩的原始净分；不累计带入记录。
- 下阶段带入：选定的来源分数通过结算函数生成，独立账本记录。下一阶段竞技分 = 新带入 + 下一阶段对局与处罚，不再重复加上一阶段总分。

团体赛默认转换队伍竞技分。个人表现榜保留原始累计，不跟随队伍自动折半；若赛事要转换个人竞技榜，创建单独的“个人结算方案”。团队带入不得按成员平摊，否则会伪造个人历史成绩。

### 操作流程

1. 选择本赛事源阶段、后继目标阶段、结算对象（个人/队伍）、来源口径、晋级对象。
2. 选择“全额带入 / 除以2 / 清零 / 自定义比例（分子分母）”，选择处罚是否压缩及小数规则；默认方案可设 /2，但不自动执行。
3. 生成预览：姓名/队伍、来源基础分、处罚、来源竞技分、原始名次、理论转换值、舍入值、人工调整、最终带入、调整后名次、晋级状态。
4. 可逐行修改最终带入分；必须输入修改原因，系统保存理论值、覆盖值及差额。改变公式或来源后，原预览失效，明确清空或重基人工覆盖，不能悄悄沿用过时覆盖。
5. 查看影响汇总及警告，保存方案草稿；最终确认时重新校验来源版本和完整性，原子写入一次带入记录并锁定源阶段。预览不影响公开榜单。
6. 已结算方案展示只读快照；撤回/重做须记录原因。目标阶段已发生对局时需依赖关系与影响预览，不直接删除结算结果。

### 精度与负分

不使用二进制浮点作为账本真值。分数存整数最小单位，比例存分子分母；保留理论精确值并在结算边界按配置舍入。

预览必须解释舍入方向：向正无穷取整到 0.1、向负无穷取整到 0.1、截断趋零、四舍五入（中点远离零），或在正式引擎中保留 0.01 的方案。每次规则保存明确精度和负分行为。
示例：101.3 / 2 = 50.65，-101.3 / 2 = -50.65；若选向正无穷到 0.1，得到 50.7/-50.6。该例是程序可选策略演示，不将其未经核实地标为各赛季 ML 官方策略。

## 七、展示页面与筛选（R06）

| 页面 | 展示内容 | 筛选 |
| --- | --- | --- |
| 总赛程 | 日历/列表、赛事、阶段、比赛日、桌号、半庄、计划/实际时间、选手/队伍、待赛/进行/完赛/取消 | 赛事或有权访问的全部赛事、类型、阶段、日期范围、桌号、选手、队伍、状态 |
| 总对局结果 | 半庄及四人成绩、基础积分、罚分、净分、角色/队伍、役满、规则版本、发布时间、更正标识 | 赛事、阶段、日期、桌号、选手、队伍、状态、仅有罚分、仅有役满、关键字 |
| 队伍榜 | 名次、队伍、场次、基础贡献、处罚、原始净分、带入、竞技分、役满次数、晋级线 | 单一团体赛事、阶段、竞技分/原始累计、队伍关键字、资格状态；日期子集另标统计榜 |
| 个人榜 | 名次、选手、当前及历史所属队伍、场数、总/均积分、平均顺位、1~4位次数、罚分、役满次数 | 单一赛事、阶段、队伍、选手、时间范围、最少场数、统计口径 |

筛选使用 AND 组合；清空按钮、结果条数、空结果提示和可分享查询参数。切换赛事时刷新过滤选项；跨赛事仅列表汇总不混算榜单。正式版分页和排序在服务器执行，导出保留筛选条件、规则版本与统计口径。

观众端只能看到已公开赛事及已发布战果，不可通过状态参数获取草稿/处罚内部备注。管理端可以筛选草稿、待审和更正版本，但默认仅最新有效版本进入统计。

“队伍/选手关键字”默认只隐藏不匹配行，不改变其官方名次；“日期/场数/仅有役满”等切片重算应明确标为自定义统计，不能冒充正式晋级榜。个人平均顺位遇同位使用所占顺位的平均名次，不能把并列第一都当 1.0 计算。

只录终局战果时无法可靠计算和牌率、放铳率、副露率；不在第一版伪造这些数据。

## 八、界面与 PWA

完整程序名用于浏览器标题、登录页、页眉、manifest name；手机图标短名用“欢雀楼”。
管理导航：赛事管理、成绩录入、罚分/役满事件、阶段结算、计分规则、总赛程、总对局结果、队伍榜、个人榜。
展示端以赛事首页和四个查询页为主；手机筛选可折叠，录入用选手卡片避免宽表挤压。
正式版 PWA 使用 HTTPS、manifest 和应用图标，支持添加桌面；当前原型不宣称已经具备安装能力。离线公开赛果标缓存时间，后台不离线发布，不缓存私密接口响应。

## 九、数据与实施约束

主要实体：Tournament、TournamentRole、Participant、Team、Membership、Stage、RuleVersion、Match、SeatResult、Penalty、YakumanEvent、SettlementPlan、SettlementLine、CarryEntry、AuditLog。
成绩、处罚、结算保存版本号；发布幂等键防止重复入账；结算方案绑定 source_revision。所有子记录使用赛事复合关联或等效校验，测试跨赛事 ID 注入被拒绝。

数据布局继续遵守 /data/majiang/dev 与 /data/majiang/prod。附件按赛事和事件归档；数据库可共享服务但业务行隔离，必要时独立 schema，不为每场比赛随意安装一套数据库。
本机原型只保存代码，演示数据在页面内存；真实业务数据以服务器数据库为唯一真值，不存浏览器 localStorage。生产与开发用户、数据库、凭据、端口、缓存、日志独立。

## 十、验收用例与原型边界

- 同一选手参与两赛事：罚分/役满/结算仅影响所属赛事；跨赛接口和导出越权失败。
- 个人赛无队伍必填项；团体赛验证当场成员归属；转队不影响历史队伍贡献。
- 20.0 罚分带原因后只扣一次；仅个人/仅队伍/两者分别验证。标记役满后积分不变，同场两个役满都可保留。
- 普通得分、负点数、2/3/4人同分、未结供托、供托留存模板、联盟条件顺位表、模板与规则版本变更。
- 预览 /2 对正分、负分和奇数最小单位正确处理；人工覆盖必须有原因；预览不改榜；重复确认不重复带入。
- 修改源战果或晋级人选后旧预览不可确认；有未完赛对局不能结算；个人/队伍带入互不污染。
- 全阶段原始累计不重复计算带入；阶段官方榜清楚展示带入项；不同赛事不合并排名。
- 四个查询页筛选、重置、无结果、手机布局和权限可见性。

v2 原型演示范围：多赛事创建/切换、个人/团体分支、罚分与多条役满录入、四查询页筛选、阶段转换预览与逐行覆盖/原因、演示结算、赛事级规则编辑。示例在内存中运行，刷新清空。未核实的联盟模板和完整最高位战规则在正式启用前仍需完成核对；原型明确标注参考或待核实，不代表官方完整规则认证。
正式登录授权、真实数据库、多人并发、生产发布、附件上传、全部筛选维度、完整规则引擎和 PWA 安装仍是实施工作，不因原型可点击就视为已完成。
