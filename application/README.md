# 欢雀楼赛事管理程序

第一版开发实现，2026-09-06。采用 Django 5.2、服务端会话与 CSRF 保护、PostgreSQL 18 持久化，电脑与手机共用网页。锁定版本见 requirements.lock。

## 开发访问

服务器：127.0.0.1:8770，systemd 服务 hql-dev，以 majiang-dev 运行。通过工作主机 SSH 隧道映射本机 8780。

- `/manage/`：登录后管理赛事。
- `/`：无需登录的观众端，只展示公开赛事与已发布赛果。
- `/data.json`：公开数据投影，未公布出战名单不输出选手 ID，草稿成绩不输出。
- `/health/`：服务与数据库连通检查。

本机运行 `start-development.ps1` 或双击 `打开开发环境.cmd`。原设计预览 8767/8768 保留。

初始开发管理员 hql-admin，登录资料保存在 `/data/majiang/dev/config/admin-login.txt`。Django 签名密钥在同一 config 目录。不能把这些文件提交到 Git。

## 已实现

赛事级授权；个人/团体赛创建；阶段、队伍和赛事级报名新增；规则新版本及对局快照；队伍优先排期与出战名单公布；服务器重新计算四人成绩；草稿与发布分离；个人、队伍或两者范围罚分；役满事件；已发布成绩带原因更正；乐观并发版本校验和完整修改前后审计。

## 数据与部署

开发环境根目录 `/data/majiang/dev`；数据库 `data/postgres`，Unix socket `data/pg-run`，数据库日志 `logs/postgres`，日志 `logs`，依赖 `venv`，缓存 `cache`，临时文件 `tmp`，配置 `config`。源代码在 `app/application`。启动依赖 `/data` 挂载，安装脚本核验数据盘 UUID。

Event.document 是单赛事原子聚合，所有引用只在该赛事内解析。每次写入使用数据库条件 UPDATE 检查 revision，审计与业务变更在同一事务提交。Event.editors 是赛事授权关系；超级管理员可管理全部赛事。开发使用独立 PostgreSQL 18 实例（hql-postgres-dev），通过 Unix socket 的 peer 认证连接 hql_dev，不监听 TCP，不共享生产数据库。

更新：直接在远程修改代码并安装锁定依赖，在开发环境执行 `python manage.py test league`、`migrate --noinput`，再重启 hql-dev。迁移前备份已有业务数据库。生产使用独立用户、发布目录、配置、数据和端口；本次没有创建生产服务。

## 三类账号与赛事授权（2026-09-06 用户确认）

- 总管理员：管理全部赛事、创建普通账号、创建赛事、授予或撤回子赛事管理员权限。
- 子赛事管理员：完整管理被授权赛事的名单、规则、赛程、成绩、公开状态和结算；不能创建账号、创建赛事或给他人授权。
- 普通账号：只能查看公开赛事，不得访问管理页面或私有赛事接口。无需登录的观众同样可查看公开展示。

不区分录入员和审核员。一个账号可以管理多个指定赛事，撤回全部授权后恢复普通账号。总管理员的全局权限不受单赛事授权列表限制；不通过前端隐藏来代替权限校验。旧编辑者关系保留为子赛事管理员。

总管理员在“赛事授权”页创建普通账号、配置指定赛事授权。授权操作校验赛事 revision，与成员关系和审计记录同事务提交。撤回会使旧页面版本失效；所有接口重新检查当前授权。新账号强制非 staff、非 superuser，客户端不能指定更高权限。

验证：39项后端测试通过，覆盖账号创建、防提权、跨赛事隔离、子赛事完整业务权限、普通账号只读以及撤回最后一名子赛事管理员后总管理员仍可管理。

## 个人赛高高碰（2026-09-13）

管理端个人赛新增“高高碰排程”。首轮按报名序号自然排序，每四人一桌；之后每半庄全桌成绩发布后，按当前阶段竞技分（含带入及罚分）降序重新分桌，同分按报名序号，桌内随机座次。转阶段首轮按带入后的阶段竞技分分桌。

预览可调整分桌及座次，备注选填。确认后生成一轮赛程并公布出战名单，不自动生成成绩。相同桌号可在不同开赛时间使用。人数须为4的倍数、每人恰好一次、场次一致、晋级资格与阶段状态有效；过期预览或并发变更须重新预览。保留编排时排名和操作记录，之后更正成绩不自动改排已生成赛程。

104项PostgreSQL回归通过；实际浏览器完成电脑/390px手机预览、不填原因调整、第二轮排程及归档清理。临时验收赛事已清理。开发数据库备份：/data/majiang/dev/backups/before-pairing-20260913.dump。

## 角色权限约定（2026-09-18 用户确认）

- 总管理员：所有赛事管理、创建并授权赛事管理员，以及开启归档修订。
- 赛事管理员：自己的未归档赛事业务管理，创建本赛事教练、停用/恢复及移除教练授权；不可创建赛事管理员或管理其他赛事。
- 教练：公开查询及指定选人大会的教练操作，不获得赛事后台权限。
- 观众：公开查询，无业务写权限。
- 归档后赛事管理员只读；总管理员在“结束与归档”开启修订，观众端继续使用上次归档结果，完成修订时重新归档并生成排名与导出。已有阶段结算依赖仍校验，不自动篡改带入分。
- 删除、编辑属于业务权限；引用完整性、点数、阶段结算依赖和并发版本校验对所有角色生效。赛程支持日期/时间/桌号修改及未结算对局删除，删除已发布战果会重新计算排行并保留审计。
